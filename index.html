Manual y Guía de Ingeniería de Prompts

Una guía completa, interactiva y estructurada para dominar el arte y la ciencia de comunicarse con Modelos de Lenguaje (LLMs).

🎯 Objetivo del Manual

La Ingeniería de Prompts (Prompt Engineering) es la disciplina de estructurar textos e instrucciones para que un modelo de inteligencia artificial genere las respuestas más precisas, útiles y coherentes posibles.

Capítulo 01

Fundamentos de Prompt Engineering

Conceptos esenciales para entender cómo procesan los LLMs las instrucciones de entrada.

1. Anatomía de un Prompt Perfecto

Un prompt profesional bien estructurado suele estar compuesto por cuatro elementos fundamentales:

1. Rol / Persona: Define la identidad y perspectiva del modelo (ej: "Actúa como un arquitecto de software senior...").
2. Instrucción / Tarea: La acción clara y específica que debe realizar el modelo (ej: "Analiza el siguiente código y detecta vulnerabilidades de seguridad.").
3. Contexto / Restricciones: Información de fondo, formato de salida deseado o límites (ej: "Responde solo en JSON. Máximo 200 palabras.").
4. Entrada / Datos: El texto, código o información que debe procesarse.

2. Tokens y Ventana de Contexto

Los modelos de lenguaje no leen palabras completas sino tokens (subpalabras o grupos de caracteres). En promedio, 100 tokens equivalen a unas 75 palabras en inglés o ~50 palabras en español.

  • Context Window: Es la cantidad máxima de tokens (entrada + salida) que el modelo puede retener en un turno. Por ejemplo, 128k tokens en modelos modernos.
  • Atención: Las instrucciones colocadas al inicio y al final del prompt reciben mayor atención ("Efecto Primacía y Reciente").

Zero-Shot y Few-Shot Prompting

Aprende a solicitar respuestas directas o proveer ejemplos guía antes de solicitar la respuesta.

Consiste en pedir al modelo que realice una tarea sin proporcionarle ningún ejemplo previo. Confía en el conocimiento previo que el LLM adquirió durante su entrenamiento.

2. Few-Shot Prompting

Proporciona 1, 2 o más ejemplos (shots) de entrada y salida esperada antes del problema real. Es ideal para estandarizar formatos de salida o condicionar estilos específicos.

Capítulo 03

Chain-of-Thought (CoT)

Forzar al modelo a razonar paso a paso para resolver problemas lógicos, matemáticos y de razonamiento complejo.

1. ¿Qué es Chain-of-Thought?

Chain-of-Thought (Cadena de Pensamiento) desglosa problemas complejos en pasos intermedios de razonamiento antes de emitir una respuesta final. Reduce drásticamente los errores en matemáticas, código y lógica deductiva.

🚀

Zero-Shot CoT: El Prompt Mágico

Agregar simplemente la frase "Razona paso a paso antes de responder:" o "Let's think step by step:" al final de una consulta aumenta la precisión del modelo en tareas de lógica hasta en un 40%.

Pregunta: Roger tiene 5 pelotas de tenis. Compra 2 latas más de pelotas de tenis. Cada lata tiene 3 pelotas de tenis. ¿Cuántas pelotas de tenis tiene ahora?

Pregunta: La cafetería tenía 23 manzanas. Si usaron 20 para hacer almuerzos y compraron 6 más, ¿cuántas manzanas tienen?

Capítulo 04

Role Prompting & Personas

Condiciona el tono, perspectiva, profundidad técnica y estilo de respuesta mediante asignación de roles.

1. Asignación de Roles

Al indicarle al modelo qué personaje o profesional debe encarnar, activas clusters latentes de conocimiento especializado y ajustas el vocabulario automáticamente.

👨‍💻

Rol: Senior Code Reviewer

"Actúa como revisor principal de código en Rust. Evalúa rendimiento, manejo de memoria y elegancia."

👩‍🏫

Rol: Maestro para Niños

"Explica la teoría de la relatividad usando analogías sencillas como si yo tuviera 8 años."

⚖️

Rol: Auditor Regulatorio

"Analiza la siguiente política de privacidad identificando riesgos bajo la normativa GDPR de la UE."

Formato y Delimitadores

Estructuración de prompts mediante delimitadores claros, etiquetas XML y esquemas JSON.

1. Uso de Delimitadores de Texto

Utilizar delimitadores claros evita ataques de Prompt Injection (donde el texto de entrada intenta cambiar las instrucciones) y aclara qué parte es instrucción y qué parte son datos.

Uso de Delimitadores y Etiquetas XML 
Resume el texto contenido dentro de las etiquetas <articulo>. Genera 3 viñetas breves.

</articulo>

2. Salidas JSON Estructuradas

Para integrar la salida del LLM directamente en APIs o aplicaciones frontend/backend, exige esquemas JSON estrictos.

Capítulo 06

ReAct y Tree of Thoughts (ToT)

Patrones avanzados para agentes autónomos y resolución de problemas por exploración de árboles de pensamiento.

1. El Patrón ReAct (Reasoning + Acting)

ReAct combina el razonamiento analítico con la ejecución de acciones u herramientas externas (búsquedas en la web, ejecuciones de código o consultas a bases de datos) en un bucle interactivo.

Estructura del Bucle ReAct 
Pensamiento 1: Necesito averiguar la temperatura actual en Bogotá.
Acción 1: BuscarWeather[Bogotá]
Observación 1: La temperatura en Bogotá es 18°C con cielo parcialmente nublado.

Pensamiento 2: Ahora debo convertir 18°C a Fahrenheit para responder la pregunta completa.
Acción 2: Calculator[18 * 9/5 + 32]
Observación 2: 64.4

Pensamiento 3: Ya tengo todos los datos necesarios.
Respuesta Final: La temperatura en Bogotá es 18°C (64.4°F).

2. Tree of Thoughts (ToT)

ToT permite explorar múltiples caminos de pensamiento simultáneamente (como en un árbol de decisión), evaluando cada opción antes de decidir cuál continuar. Ideal para planificación estratégica y juegos como el ajedrez.

Capítulo 07

Chaining, Self-Consistency y RAG-Aware

Estrategias complejas para encadenar múltiples prompts, verificar respuestas y redactar con contexto recuperado.

1. Prompt Chaining (Encadenamiento)

Descompone una tarea masiva en una serie de prompts individuales donde la salida del Prompt N se convierte en la entrada del Prompt N+1. Evita la sobrecarga cognitiva en una sola llamada.

2. Self-Consistency (Auto-Consistencia)

Genera múltiples rutas de razonamiento independientes (con `temperature > 0`) para la misma pregunta y elige la respuesta más votada o frecuente. Elimina fluctuaciones estocásticas.

3. RAG-Aware Prompting

Técnica para instructing modelos a responder estrictamente basándose en fragmentos recuperados de una base de conocimiento, evitando alucinaciones.

Capítulo 08

Mejores Prácticas y Consejos

Reglas de oro para optimizar y auditar prompts en producción.

  • Sé positivo y directo: Indica qué hacer en lugar de qué no hacer. Los modelos entienden mejor instrucciones directas ("Escribe en tono formal") que negativas ("No uses jerga informal").
  • Usa ejemplos claros: Si la tarea requiere un formato complejo, pocos disparos (Few-shot) valen más que 500 palabras de instrucciones descriptivas.
  • Ajusta la temperatura: Usa `temperature = 0.0` para tareas analíticas, extracción JSON o código. Usa `temperature = 0.7 - 0.9` para tareas creativas o brainstorming.
  • Controla el contexto: Coloca los datos de entrada al final del prompt para aprovechar el efecto de reciencia.
